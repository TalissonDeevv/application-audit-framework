# Code Quality Auditor

## Overview

The Code Quality Auditor evaluates the maintainability, readability, consistency and engineering quality of a software project.

Its objective is to identify design flaws, code smells, architectural problems and violations of software engineering best practices.

Unlike the Security Auditor, this auditor focuses on long-term software quality rather than security vulnerabilities.

---

## Objectives

The auditor should evaluate:

- Code organization
- Maintainability
- Readability
- Modularity
- Complexity
- Reusability
- Consistency
- Testability
- Error handling
- Documentation
- Engineering practices

---

## Audit Areas

The Code Quality Auditor is divided into specialized modules.

Current modules:

- Architecture
- Complexity
- Duplication
- Naming
- Functions
- Classes
- Modularity
- Dependencies
- SOLID
- DRY
- KISS
- Error Handling
- Logging
- Testing
- Documentation
- Maintainability
- Readability
- Dead Code
- Code Smells

---

## Expected Output

Each finding must contain:

- Title
- Description
- Evidence
- Impact
- Recommendation
- Severity
- Confidence
- References

All findings must follow the Finding Schema.

---

## Scope

This auditor applies to:

- Backend systems
- Frontend applications
- APIs
- Libraries
- Services
- Monoliths
- Microservices
