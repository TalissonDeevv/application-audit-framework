# Code Quality Checklist

## Project Organization

- Folder structure is consistent.
- Modules are well organized.
- Responsibilities are separated.
- Layering is respected.

---

## Maintainability

- Code is easy to modify.
- Components are reusable.
- Responsibilities are isolated.
- Technical debt is limited.

---

## Readability

- Code is understandable.
- Naming is descriptive.
- Formatting is consistent.
- Comments add value.

---

## Functions

- Functions have a single responsibility.
- Functions are reasonably sized.
- Parameters are limited.
- Return values are clear.

---

## Classes

- Classes follow Single Responsibility.
- Dependencies are minimal.
- High cohesion.
- Low coupling.

---

## Architecture

- Layers are respected.
- Dependencies flow correctly.
- Clear separation of concerns.

---

## Complexity

- No excessive nesting.
- Cyclomatic complexity is acceptable.
- Logic is simplified where possible.

---

## Dependencies

- Dependencies are justified.
- No unused packages.
- Versions are maintained.

---

## Error Handling

- Errors are handled consistently.
- Exceptions are meaningful.
- Sensitive information is not exposed.

---

## Logging

- Logs are useful.
- Sensitive data is not logged.
- Error logs are actionable.

---

## Testing

- Critical paths are tested.
- Tests are isolated.
- Tests are maintainable.

---

## Documentation

- Public APIs are documented.
- Architecture is documented.
- Important decisions are explained.

---

## Dead Code

- No unreachable code.
- No obsolete modules.
- No unused functions.

---

## Code Smells

- No God Classes.
- No God Functions.
- No Feature Envy.
- No Shotgun Surgery.
- No Long Methods.
- No Duplicate Logic.
