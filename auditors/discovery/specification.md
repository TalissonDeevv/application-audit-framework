# Discovery Specification

## Objective

Understand the project before any technical analysis begins.

---

# Input

Expected inputs include:

- Source code
- Repository structure
- Configuration files
- Documentation
- Build files

---

# Process

The Discovery Auditor should execute the following steps.

1. Identify project type.

2. Detect programming languages.

3. Detect frameworks.

4. Detect package managers.

5. Detect build tools.

6. Detect runtime.

7. Detect databases.

8. Detect ORMs.

9. Detect APIs.

10. Detect deployment configuration.

11. Detect infrastructure configuration.

12. Build the project inventory.

---

# Output

The final output should include:

- Project metadata
- Technologies
- Frameworks
- Dependencies
- Infrastructure
- Runtime
- Deployment
- Build tools

---

# Completion Criteria

The Discovery Auditor is complete when:

- The project inventory has been generated.
- The project structure has been identified.
- Technologies have been classified.
- Missing information has been documented.

---

# Limitations

The Discovery Auditor must not:

- Detect vulnerabilities.
- Score the project.
- Recommend changes.
- Infer missing information.
