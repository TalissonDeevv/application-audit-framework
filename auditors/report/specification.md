# Report Auditor Specification

## Purpose

Transform audit findings into a structured report that supports technical decision-making and project improvement.

---

# Responsibilities

The Report Auditor must:

- Aggregate findings.
- Validate report consistency.
- Group similar findings.
- Preserve evidence.
- Organize findings by category.
- Calculate project metrics.
- Produce executive summaries.
- Produce technical summaries.
- Generate recommendations.
- Generate implementation roadmaps.

---

# Inputs

The Report Auditor receives:

- Findings
- Severity
- Confidence
- Evidence
- References
- Categories
- Metadata
- Project Information

---

# Outputs

The auditor produces:

- Executive Report
- Technical Report
- Findings Summary
- Risk Analysis
- Severity Distribution
- Confidence Distribution
- Recommendations
- Roadmap
- Final Score

---

# Processing Flow

1. Receive findings.

2. Validate structure.

3. Remove duplicates.

4. Normalize terminology.

5. Group by category.

6. Prioritize issues.

7. Calculate metrics.

8. Build report.

9. Validate consistency.

10. Publish report.

---

# Validation Rules

The Report Auditor must verify:

- Required fields exist.
- Evidence is present.
- Severity is valid.
- Confidence is valid.
- References exist.
- Categories are valid.

---

# Constraints

The Report Auditor must never:

- Create fictional findings.
- Remove valid findings.
- Modify evidence.
- Change severity arbitrarily.
- Ignore Critical findings.

---

# Success Criteria

A successful report:

- Represents all findings.
- Preserves traceability.
- Is technically consistent.
- Supports remediation.
- Supports executive decisions.
